#api設計
## 大原則
- API一覧として、機能・メソッド・URL・ボディ・成功時のステータス・成功時のレスポンス・エラーのレスポンス及び内容について整理する
- URLはメソッドを実施する対象を書く。対象となるもの（memos）、削除や検索などmemosの中でさらに対象が必要なもの（削除するid, 検索するキーワードなど）も続けて書く
- 2xxは成功、4xxは頼み方を直せば成功するクライアント側の誤り、5xxは開発側が直す必要のあるサーバーの誤り
- 使う人の視点で考える。使う人から見えるのはAPI(窓口)まで、その中身についてはわからない。そのため中身を変える際はクライアントのだすインプットとアウトプットの対応関係が一致していることが大事
- GETにはボディをつけない。条件はURLのクエリパラメータ（?keyword=）で渡す
- 0件は成功（200+[]）。結果がないことはエラーではない


## 設計するAPI
### 追加(add)
- メソッド：POST
- URL： /memos
- ボディ： {"content": "牛乳を買う"}
- 成功時のステータス：201（リクエストが成功し、サーバー側に新しいデータが無事に作成/登録された）
- 成功時のレスポンス：{"id": 1, "content": "牛乳を買う", "created_at": "2026-11-03T10:15:00+09:00"}
- エラー：422(contentが空、空白だけ・改行を含む)
### 一覧表示(list)
- メソッド：GET
- URL： /memos
- ボディ：なし
- 成功時のステータス：200(リクエストが完全に成功し、サーバーが正常に処理を完了した)
- 成功時のレスポンス：[{"id": 1, "content": "牛乳を買う", "created_at": "2026-11-03T10:15:00+09:00"}, {...}] (0件なら[])
- エラー：なし
### 検索(search)
- メソッド：GET
- URL：/memos?keyword=牛乳
- ボディ：なし
- 成功時のステータス：200
- 成功時のレスポンス：一覧と同じ形（0件なら[]）
- エラー：422(リクエストの書き方や形式はあっているけれど、データの中身に問題があるのでサーバー側で処理できない、keywordが空、空白だけ)
### 削除(delete)
- メソッド：DELETE
- URL：/memos/{id}
- ボディ：なし
- 成功時ステータス：200
- 成功時のレスポンス：{"id": 2, "content": "牛乳を買う", "created_at": "2026-11-03T10:15:00+09:00"}
- エラー：404:idのメモがない、422:idが整数でない
